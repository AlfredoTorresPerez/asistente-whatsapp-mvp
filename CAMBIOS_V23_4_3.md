# Cambios V23.4.3 - Logger transversal de trazabilidad IA

## Objetivo
Agregar trazabilidad por consola para seguir un mensaje desde su entrada por WhatsApp hasta la respuesta final de IA, sin modificar la logica funcional aprobada en V23.4.2.

## Cambios principales

- Se agrega `AiTraceLogger` como utilidad central para logs `[AI_TRACE]`.
- Se agrega `traceId` al `AgentConversationRequest` para propagar correlacion entre capas.
- Se instrumenta entrada WhatsApp en `WhatsAppWebWebhookService`.
- Se instrumenta previsualizacion IA en `ConversationService`.
- Se instrumenta orquestacion en `AgentCoordinatorService`.
- Se instrumenta normalizacion y extraccion en `EntityExtractionService`.
- Se instrumenta candidatos de intencion en `IntentDetectorService`.
- Se instrumenta flujo de agenda en `BookingAgent`.
- Se instrumenta resolucion de servicio, sucursal, disponibilidad, reserva temporal y enlace en `TransactionalAgendaBookingService`.
- Se configura nivel INFO para `com.asistentewhatsapp` y `AI_TRACE` en `application.yml`.
- Se agrega `test_ia_negocio_conversacional_v23_4_3.ps1` con instrucciones para ver/exportar logs.

## Pasos observables esperados

Al enviar una reserva completa, la consola debe mostrar pasos como:

```text
[AI_TRACE] step=WHATSAPP_MESSAGE_RECEIVED ...
[AI_TRACE] step=CONVERSATION_CONTEXT_LOADED ...
[AI_TRACE] step=MESSAGE_NORMALIZED ...
[AI_TRACE] step=INTENT_CANDIDATES ...
[AI_TRACE] step=INTENT_DETECTED ...
[AI_TRACE] step=ENTITIES_EXTRACTED ...
[AI_TRACE] step=EFFECTIVE_LOCATION_RESOLVED ...
[AI_TRACE] step=SERVICE_RESOLVED ...
[AI_TRACE] step=SERVICE_LOCATION_VALIDATED ...
[AI_TRACE] step=BOOKING_REQUIRED_DATA_CHECK ...
[AI_TRACE] step=AVAILABILITY_CHECK_STARTED ...
[AI_TRACE] step=AVAILABILITY_CHECK_RESULT ...
[AI_TRACE] step=TEMPORARY_BOOKING_CREATED ...
[AI_TRACE] step=CONFIRMATION_LINK_CREATED ...
[AI_TRACE] step=AI_FINAL_RESPONSE ...
[AI_TRACE] step=WHATSAPP_RESPONSE_SEND_STARTED ...
[AI_TRACE] step=WHATSAPP_RESPONSE_SEND_RESULT ...
```

## Seguridad

- Telefonos se registran enmascarados.
- Tokens de confirmacion se registran enmascarados.
- URLs con `/reservas/confirmar/{token}` se sanitizan en logs.
- No se registran cabeceras `Authorization` ni secretos.
